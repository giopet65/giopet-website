# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Overview

Static "site under construction" for giopet.eu (personal site of an IT consultant / Solution Architect), hosted on GitHub Pages (custom domain via `CNAME`). The home page is HTML/CSS/vanilla JS but is also a Jekyll page (it lists the latest articles via Liquid); the **articles section** (`it/articles/`, `en/articles/`) is Markdown compiled by Jekyll, which GitHub Pages runs on every push to `main` (no GitHub Action, no tests, no linter; Ruby/Bundler are used only for the local preview). Deploying = pushing to `main` (the history has "Rilancio deploy" commits, i.e. empty/re-trigger commits to re-run Pages).

Preview: since the home is a Jekyll page too, opening `index.html` directly shows raw Liquid. Use the local Jekyll (Ruby 3.3 + Bundler installed on the user's PC; [Gemfile](Gemfile) pins `github-pages`, so versions match GitHub's): `bundle exec jekyll serve` from the repo root, then open `http://localhost:4000`. Changes reload by themselves, except `_config.yml` which needs a restart. On this machine Ruby is not on the PATH of Claude's shell: use `export PATH="/c/Ruby33-x64/bin:$PATH"`, and to verify a build without touching the user's server use `bundle exec jekyll build -d <scratchpad>/_site`. `_site/`, `.jekyll-cache/` and `Gemfile.lock` are git-ignored. Always check the live pages after the deploy too.

The README is a one-liner. Converse with the user in Italian; code comments and commit messages are also in Italian, so keep them that way. The site content itself is bilingual (Italian and English).

## Git rule

Never run `git commit` or `git push` without the user's explicit request. Consent applies only to that single request: when work is done, stop and propose the commit instead of making it.

## Architecture

- [index.html](index.html): Jekyll page (empty front matter, no layout) with the markup, SEO/OpenGraph meta, the latest 2 articles per language (variable `latest_count`; both IT and EN lists are in the HTML, the EN one `hidden`, `script.js` shows the active language and updates the "all articles" link; cards come from `_includes/article-card.html`, shared with the full list), and the contacts below the articles. Asset paths are absolute (`/style.css`, …). Also holds and a tiny inline script in `<head>` that adds the `js` class and applies the saved theme (`localStorage` key `giopet-theme`) before first paint to avoid flicker. The language/theme toggles live in `#topbar`, which is `hidden` until JS runs.
- [script.js](script.js): one IIFE. Holds the **IT/EN translation table `T`** (page strings, mailto subject, last-updated date, privacy text, and the boot-log lines rendered into `#term`). `applyLang()` fills elements via `data-i18n` (textContent) and `data-i18n-html` (innerHTML) attributes, updates `<html lang>`, title and the mailto link. `play()` drives the intro sequence (copper trace draws → LED pill turns on → log rows appear), by toggling classes `run` / `on` / `shown`; with `prefers-reduced-motion` everything is shown immediately. Language persists in `localStorage` key `giopet-lang`.
- [style.css](style.css): "graph paper" theme with CSS custom properties in `:root`; dark theme is applied both automatically (`prefers-color-scheme`) and explicitly via `:root[data-theme="dark"]`. The hero "circuit" is built from fixed-px SVG segments plus stretchy `.run-line` spans; the geometry comment near line 205 explains the fixed 36px box / y=18 alignment, so keep these in sync when editing the trace. Fonts are self-hosted in `fonts/` (SIL OFL licenses included).
- [404.html](404.html): standalone error page.
- Folders: `img/` holds all images (favicon, `og-image.png` referenced by absolute URL in the OpenGraph meta, so keep that path stable: social platforms cache it; article images go in `img/articles/<data>-<id>/`), `fonts/` the self-hosted fonts, `docs/` the project documentation (not published).
- [_config.yml](_config.yml): Jekyll setup. `exclude` keeps `CLAUDE.md`, `README.md` and `docs/` off the site; `defaults` derive `lang` and `layout` from the folder (`it/articles` / `en/articles`); `permalink: pretty` gives URLs without extension; `jekyll-sitemap` builds `sitemap.xml` (`robots.txt` points to it). Drafts use `published: false`.
- Articles: Markdown files `<AAAAMMGG>-<NN>-<titolo>.md` in `it/articles/` and `en/articles/` (the language comes from the folder, no `-IT`/`-EN` suffix). The `<data>-<id>` prefix is identical in the two languages: `_layouts/default.html` uses it to find the translation (language toggle, `hreflang`), `_includes/article-date.html` derives the date from it, and it names the image folder. Layouts: `article.html`, `article-list.html` (both on top of `default.html`). Fixed UI strings are in `_data/i18n.yml`; [article.js](article.js) only handles the theme toggle and remembers the language. Article styles are in the "Articoli" section of style.css (code colours are Rouge token classes).

## Conventions to preserve

- **Progressive enhancement**: without JS the page must still be complete (text visible, trace drawn, LED on). CSS animation rules are scoped to the `.js` / `.run` classes for this reason; don't make content depend on JS.
- **Bilingual content**: any user-visible string change must be made in both `T.it` and `T.en` in script.js, *and* in the Italian fallback text in index.html (the default markup is Italian and is what no-JS users and crawlers see). Update the last-updated date (`T.*.date`, the `<time>` element, and "rev." in the footer) together.
- **Articles workflow**: the user writes the Italian article, Claude imports it and writes the English translation (same `<data>-<id>` prefix, English title in the file name), the user reviews it. The full process (naming, front matter, images, translation rules, checks before and after publishing) is in [docs/processo-articoli.md](docs/processo-articoli.md); follow it. File names in this repo are lowercase. Open ideas live in [docs/backlog.md](docs/backlog.md).
- **Privacy stance**: the page claims no cookies, no analytics, no forms and no external requests beyond the GitHub privacy link; don't add trackers, CDNs or external fonts without updating the privacy text in both languages (home: `T.*.privacy` in script.js; articles: `privacy` in `_data/i18n.yml`).
